# MCP простыми словами (Model Context Protocol)

> 📖 Красиво смотреть: `Cmd+Shift+V` (Windows: `Ctrl+Shift+V`).

## Понятнее всего на примере

Помнишь инструменты из `01-pure_python/11_real_tools.py` (погода, озвучка,
уведомления)? Там инструмент был «вшит» в одного бота. **MCP — это способ вынести
такие инструменты наружу**, чтобы ими пользовался кто угодно, а не один скрипт.
Под капотом — та же идея «у агента есть руки», просто руки теперь общие.

## Что это

**MCP — это «USB-разъём» для инструментов ИИ.** Раньше каждый инструмент
(погода, база данных, календарь) приходилось вшивать в КОНКРЕТНОГО бота. С MCP ты
**один раз** пишешь «сервер инструментов» — и его понимает **любой** клиент:
Claude Desktop, Claude Code, твоя IDE, другие приложения.

```
Раньше:   каждый бот    →  свой код инструментов  (всё заново)
С MCP:    один MCP-сервер  ←  подключаются любые клиенты (Claude Desktop, IDE, ...)
```

Аналогия: USB. Один разъём — и к компьютеру подходят мышь, флешка, принтер.
MCP — такой же общий «разъём», только для инструментов ИИ.

## MCP и обычный API — в чём разница

Логичный вопрос: «но ведь у сервисов и так есть API — зачем ещё MCP?»

**API** — это «дверь» в конкретный сервис (у погоды своя, у CRM своя, у банка
своя). У каждой двери — свой замок, свои правила, своя инструкция. Чтобы ИИ
воспользовался десятью сервисами, программисту надо вручную написать код под
каждый из десяти API отдельно.

**MCP** — это **единый стандарт поверх этих дверей**. Ты один раз оборачиваешь
сервис в MCP-сервер — и дальше любой ИИ-клиент пользуется им **одинаково**, не
зная деталей каждого API.

| | Обычный API | MCP |
|---|---|---|
| Стандарт обращения | у каждого сервиса свой | **один общий** для всех |
| Кто пишет интеграцию | программист — под каждый API руками | подключил сервер — и готово |
| Кто вызывает | твой код → API | **сам ИИ-агент** → MCP-сервер |
| Появился новый сервис | пиши новый код интеграции | просто подключаешь его MCP-сервер |

Наглядно, как меняется схема:

```
РАНЬШЕ (только API):
   твой код ──свой код интеграции──> API погоды
   твой код ──свой код интеграции──> API CRM
   твой код ──свой код интеграции──> API банка
   (под каждый сервис — отдельный код, и пишет его программист)

ТЕПЕРЬ (через MCP):
                       ┌─> MCP-сервер погоды ──> API погоды
   ИИ-агент ──единый──>├─> MCP-сервер CRM    ──> API CRM
            способ     └─> MCP-сервер банка  ──> API банка
   (агент общается со всеми ОДИНАКОВО; API остаётся под капотом)
```

> ⚠️ Важно: **MCP не заменяет API, а стоит НАД ними.** Внутри MCP-сервер обычно
> сам дёргает обычный API (наш `get_weather` под капотом ходит на сайт погоды).
> MCP лишь делает так, чтобы для ИИ все инструменты выглядели и вызывались
> **одинаково** — как USB-разъём прячет различия мыши, флешки и принтера.

## Зачем это тебе

- Написал инструмент один раз — пользуешься им везде, где есть MCP.
- Не надо вшивать инструменты внутрь каждого бота.
- Куча **готовых** MCP-серверов уже существует (файлы, GitHub, базы данных,
  поиск и т.д.) — подключаешь и пользуешься, не пишешь сам.

## Две стороны MCP

| Сторона | Что это | Пример |
|---|---|---|
| **MCP-сервер** | программа, которая ОТДАЁТ инструменты | наш `06-mcp/server.py` (погода + калькулятор) |
| **MCP-клиент** | программа, которая ПОЛЬЗУЕТСЯ инструментами | Claude Desktop, Claude Code, IDE |

В папке `06-mcp/` лежит **минимальный сервер** — чтобы потрогать руками, как это
устроено. Запуск и подключение — в `06-mcp/README.md`.

## Где брать готовые MCP-серверы

Есть открытые каталоги MCP-серверов (файловая система, GitHub, Slack, Postgres и
многое другое). Обычно подключаются в пару строк конфига — писать код не нужно.

## А есть ещё другие протоколы? (A2A и т.п.)

Да, появляются новые. Самый заметный «сосед» MCP — **A2A (Agent-to-Agent)**,
протокол от Google. Не путай их — они про РАЗНОЕ:

| Протокол | Кто с кем общается | Простыми словами |
|---|---|---|
| **MCP** (Anthropic) | агент ↔ **инструменты/данные** | «дай ИИ руки»: погода, файлы, база |
| **A2A** (Google) | агент ↔ **другой агент** | «пусть агенты договариваются между собой» |

То есть MCP подключает к ИИ инструменты, а A2A — позволяет нескольким агентам
(возможно, от разных команд и на разных фреймворках) работать вместе.

> 🧭 Это молодая область, протоколы ещё устаканиваются. Запоминать наизусть не
> надо — достаточно знать, что **MCP = агент и инструменты**, **A2A = агент и
> агент**. На практике сейчас чаще всего встречается именно MCP.
